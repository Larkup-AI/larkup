<Badge color="blue">Developer</Badge>

Once you have created an Agent and published a release, you can put it on any
website as a floating chat bubble. The whole install is one line.

```html
<script async src="https://your-larkup-host/api/widget.js" data-agent="support-bot-m1a2b3"></script>
```

Paste it before `</body>`. The widget reads its server address from the script
URL, so nothing else is required.

## Getting the snippet

Open **Settings → Agents**, find your agent, and click **Connect**. The dialog
gives you the exact snippet for your agent and host, plus the two things you
need to configure: **allowed origins** and **appearance**.

## Allowed origins

The browser never receives a secret — it only carries your public Agent ID. The
control that stops another website from embedding your agent (and spending your
model budget) is the allowed-origins list.

Add every domain that will host the widget:

| Entry                          | Matches                                             |
| ------------------------------ | --------------------------------------------------- |
| `https://www.example.com`      | that exact origin                                   |
| `https://*.example.com`        | any subdomain — `shop.`, `eu.shop.` — but not the apex |
| `example.com`                  | the host over both `http` and `https`, any port     |
| `*`                            | every website on the internet                       |

Requests from a domain that is not on the list are rejected with `403` before
the agent runs, and the widget shows the visitor nothing but an explanatory
notice.

<Warning>
`*` is the default for a newly created agent so local development works out of
the box. Replace it with your real domains before you launch — with `*`, any
site on the internet can drive your agent.
</Warning>

Changes take effect immediately. You do **not** need to publish a new release to
add or revoke a domain, which means an origin can be revoked instantly during an
incident.

Two requests are always allowed regardless of the list:

- **Same-origin requests**, so the dashboard's own testing works.
- **Requests with no `Origin` header**, which is every server-to-server call
  from the SDKs, the CLI, and channel adapters. Those are authorized by their
  API key instead.

## Customizing the look

Everything in **Connect → Appearance** — accent colour, title, welcome message,
placeholder, position, corner style, dark mode — applies to every embed of that
agent at once.

An individual page can override any of it with `data-*` attributes:

```html
<script
  async
  src="https://your-larkup-host/api/widget.js"
  data-agent="support-bot-m1a2b3"
  data-primary-color="#0ea5e9"
  data-position="bottom-left"
  data-theme="dark"
  data-title="Sales questions"
></script>
```

| Attribute                                     | Purpose                                     |
| --------------------------------------------- | ------------------------------------------- |
| `data-agent`                                   | **Required.** Public Agent ID.              |
| `data-host`                                    | Larkup origin, if the script is on a CDN.   |
| `data-primary-color`                           | Accent colour (`#rrggbb`).                  |
| `data-position`                                | `bottom-right` (default) or `bottom-left`.  |
| `data-theme`                                   | `light` or `dark`.                          |
| `data-title`, `data-welcome-message`, `data-placeholder`, `data-avatar-url`, `data-border-radius` | Copy and shape overrides. |
| `data-open`                                    | `true` to open the panel on load.           |
| `data-join-code`                               | Join code for a gated agent.                |

Text colour on the bubble is computed from your accent colour, so a pale brand
colour still produces readable contrast.

## Controlling it from JavaScript

If you would rather mount the widget yourself — after a cookie consent banner,
on one route only, or for a signed-in user — omit `data-agent` and call `init()`:

```js
const widget = LarkupAgent.init({
  agentId: 'support-bot-m1a2b3',
  host: 'https://your-larkup-host',
  style: { primaryColor: '#0ea5e9', darkMode: true },
  defaultOpen: false,
  onReady: () => console.log('widget ready'),
  onError: (error) => console.warn(error.message),
});

// later
widget.destroy();
```

## Gating an agent with a join code

For an internal or pre-launch site, set **Auth mode** to `join-code` on the
agent and pass the code in the snippet:

```html
<script
  async
  src="https://your-larkup-host/api/widget.js"
  data-agent="internal-bot"
  data-join-code="autumn-hedgehog"
></script>
```

Every widget request must then present the code. Anyone who can view the page
source can read it, so treat a join code as a speed bump for casual access, not
as authentication for sensitive data.

<Note>
`api-key` auth mode is not enforceable yet and returns `501`. Scoped, rotatable
Agent API keys arrive with the hosted control plane. Use `none` or `join-code`
today.
</Note>

## Passing an end-user identity

If your product already authenticates its users, mint a short-lived token in
your **own backend** and hand it to the widget:

```js
LarkupAgent.init({
  agentId: 'support-bot-m1a2b3',
  host: 'https://your-larkup-host',
  headers: { Authorization: `Bearer ${shortLivedUserJwt}` },
});
```

<Warning>
Never put a secret Agent API key in `headers`, in the snippet, or anywhere else
in client-side JavaScript. Every visitor can read it. Secret keys belong on your
server.
</Warning>

## What the widget does to your page

Nothing. It mounts into a Shadow DOM, so:

- your CSS cannot restyle it, and its CSS cannot leak into your page;
- it adds one element to `<body>` and no global styles;
- it ships as a single ~69 kB gzipped file with no external requests.

## Calling the agent from a server instead

The widget and the API talk to the same endpoint. From a backend, where there is
no `Origin` header and the allow-list does not apply:

```bash
curl -N https://your-larkup-host/api/agents/support-bot-m1a2b3/chat \
  -H 'Content-Type: application/json' \
  -d '{"messages":[{"role":"user","content":"Where is my order?"}]}'
```

The response is a streaming UI Message Stream, compatible with the AI SDK's
`useChat()` on the client side. Both the flat `{ role, content }` shape above
and AI SDK `UIMessage`s with `parts` are accepted.

## Troubleshooting

**The bubble never appears.** Open the browser console. A missing or wrong
`data-agent` logs an explicit message. A missing bundle returns `503` from
`/api/widget.js` — build it with `pnpm --filter @larkup/agent-widget build`.

**The panel says the site is not in the allowed origins.** Add the exact origin
shown in the message under **Connect → Allowed origins**. Note that
`https://example.com` and `https://www.example.com` are different origins.

**The panel says the agent has no published release.** Publish one under
**Settings → Agents → Releases**.

**"Could not reach the Larkup server."** The host in the snippet is wrong or
unreachable from the visitor's network — check `data-host`, or that the server
is publicly addressable rather than on `localhost`.
